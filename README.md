# 职场嘴替（工作版）

> 不是"高情商话术生成器"，是**职场沟通的风险翻译器**：先翻译潜台词、标出风险、抽出承诺，最后才给能直接发的回复。

给 22–28 岁、刚上班 0–3 年的年轻人用。领导或客户在微信里发来一句话，你盯着对话框半小时不敢回——怕说软了被无限加活，怕说硬了被截图，怕随口一句"没问题"就变成了白纸黑字的承诺。这个工具处理的就是这半小时。

## 它和通用话术工具的区别

| | 通用高情商话术工具（如市面"嘴替"类小程序、通用大模型） | 职场嘴替（工作版） |
|---|---|---|
| 定位 | 什么场景都管：职场+恋爱+亲戚 | **只做工作**：领导/大领导/客户/HR/同事 |
| 第一步 | 直接给 6 种风格的话术 | **先翻译潜台词**：对方真正想确认什么，附原文依据 |
| 风险 | 不检查 | **每条回复过风险自检**：承诺了做不到的时间点、揽了不属于你的责、语气过卑/过硬，当场标出 |
| 承诺管理 | 无 | **把聊天抽成「任务 + 截止」**；对方没给时间点时，强制在回复里反问确认，防背锅 |
| 场景 | 大而全模板库 | 只做初入职场的 5 个时刻：被批评 / 被加活 / 被催进度 / 汇报坏消息 / 下班后收到消息 |
| 反面教材 | 无 | 每条结果附一条「千万别这样回」+ 坏在哪 |

## 痛点依据（调研摘要，2026-11）

- 知乎经久不衰的问题「回复领导用'好的'还是'收到'？」——年轻人已经把回消息总结成了公式，说明这是每天重复发生的焦虑，不是偶发事件。
- 小红书上「职场高情商」「心眼子练习」类帖子持续热门，评论区的高赞回复者被称作"互联网嘴替"——需求真实存在，但围观式求助解决不了"现在、这句、发给我的领导"的问题。
- 已有竞品验证了形态：2026 年 4 月上线的某"嘴替"类微信小程序做的是截图→6 种通用风格；应用商店里的"高情商回复"类 App 大多是恋爱话术库（约 ¥158/年）。**工作专用 + 风险校验 + 承诺抽取**这一格目前没人占。

## 功能

- **潜台词翻译**：一句话说清对方真正问的是什么 + 原文依据（如「顺便」= 在把工作量说小）
- **风险提示**：无截止时间的派活、把工作量说小、模糊授权、对比施压、情绪型批评、下班后边界
- **承诺抽取**：`{ 任务, 截止, 是否需要反问确认}`
- **三版回复**：稳妥版 / 不卑不亢版 / 推进版，每版带风险自检结论，可直接复制发送
- **千万别这样回**：一条贴近真实脱口而出的反面示例 + 具体坏在哪
- **离线可用**：默认是确定性规则引擎，零依赖、零 API Key、无网络也能跑
- **大模型模式（v0.2 新增）**：配好 API Key 后走大模型生成（提示词在 `prompts/`，输出结构与规则引擎一致）；**模型给的每条回复仍要过规则引擎的风险校验，模型说"安全"不算数**；调用失败/坏 JSON 自动回退规则引擎，结果带 `source` 徽章标明来源
- **截图输入（v0.2 新增）**：网页演示支持上传聊天截图，视觉模型一次完成"转录对话 + 分析"；没配 Key 时会明确报错"截图识别需要先配置大模型"，绝不假装识别

## 快速开始

需要 Node.js ≥ 18，无任何依赖要装。

```bash
git clone <this-repo> && cd zhichang-zuiti

# 跑测试（15 个用例: 引擎 9 + 大模型 mock 6）
npm test

# 命令行试用
node src/cli.js --text "顺便把上周的用户数据整理成表，周五下班前给我" \
--relation 直属领导 --intent 确认任务

# JSON 输入 / 输出
echo '{"text":"在吗？明天上班先把合同看一下，急","relation":"直属领导","intent":"确认任务","hour":23}' \
| node src/cli.js --stdin --json
```

关系可选：`直属领导 | 大领导 | 客户 | HR | 同事`
意图可选：`争取时间 | 委婉拒绝 | 认错说明 | 汇报进度 | 确认任务 | 请示确认`

CLI 也支持大模型：加 `--llm` 走大模型（未配置自动回退规则引擎并标明），
加 `--image <截图路径>` 走视觉模型转录+分析（未配置会明确报错、退出码 1）。

## 大模型配置（可选，不配也能用）

通过环境变量接入任何 OpenAI 兼容接口，零代码改动：

| 环境变量 | 说明 |
|---|---|
| `ZUITI_LLM_BASE_URL` | 接口地址，如 `https://api.deepseek.com` |
| `ZUITI_LLM_API_KEY` | 你的 API Key（**不要提交进仓库、不要发聊天里**，用密钥管理工具保存） |
| `ZUITI_LLM_MODEL` | 文本模型名，如 `deepseek-chat` |
| `ZUITI_VISION_MODEL` | 视觉模型名（截图识别用），不填则回退用 `ZUITI_LLM_MODEL` |

国内可直接访问的兼容接口（Base URL）：

| 服务 | Base URL |
|---|---|
| DeepSeek | `https://api.deepseek.com` |
| Kimi（Moonshot） | `https://api.moonshot.cn/v1` |
| 通义千问（DashScope 兼容模式） | `https://dashscope.aliyuncs.com/compatible-mode/v1` |

```bash
export ZUITI_LLM_BASE_URL=https://api.deepseek.com
export ZUITI_LLM_API_KEY=<你的Key>
export ZUITI_LLM_MODEL=deepseek-chat
node src/cli.js --llm --text "在吗？明天上班先把合同看一下，急" --relation 直属领导
```

> 注：仓库 CI 与本地测试用的是本地 mock 服务（`tests/mock-llm.js`）验证全链路，
> 真实模型效果以配 Key 后的实测为准。

## 网页演示

```bash
npm start          # 或 node src/server.js，端口 PORT 环境变量或默认 8788
# 打开 http://127.0.0.1:8788
```

页面：输入消息 → 出潜台词/风险/承诺/三版回复卡片（带复制按钮），
右上角徽章标明本次来源是「大模型」还是「规则引擎」；也可上传聊天截图走视觉分析。
接口：`POST /api/analyze`、`POST /api/image`、`GET /api/health`（零依赖 Node http）。

### 真实输出示例

输入：`顺便把上周的用户数据整理成表，周五下班前给我`（直属领导 / 确认任务）

```
被加活/临时加任务 直属领导 确认任务
🧭 潜台词: 直属领导在给你加一件新活, 而且心里已经默认了时间点: 周五下班前。
先确认优先级再接, 别默认你手头的事可以让路（原文依据:「顺便」）

📌 承诺抽取:
任务: 把上周的用户数据整理成表
截止: 周五下班前
需要反问确认: 否

💬 稳妥版: 收到, 我确认一下:「把上周的用户数据整理成表」, 时间点是周五下班前。
我手头还有两件在进行的, 我先把这个排进去, 周五下班前给您第一版,
排期有冲突我提前跟您说。（风险自检: 无打包票、无过度道歉、无模糊确认）

🚫 千万别这样回:「没问题, 包在我身上, 周五前肯定给您」
原因: 没对齐优先级和范围就打包票, 还钉死了时间点; 做不到时这张截图就是追责证据
```

更多示例（含被批评、下班后消息）在 [`examples/`](examples/)，均为实际运行 CLI 生成。

## 微信小程序使用

1. 微信开发者工具 → 导入 `miniprogram/` 目录（测试号即可，无需 AppID 上线）
2. 首页粘贴消息原文，选择对方关系与你的意图，点「帮我看看这句怎么回」
3. 结果按卡片展示：潜台词 → 风险提示 → 承诺确认 → 三版回复（每卡有复制按钮）→ 千万别这样回
4. 小程序调用本地 `utils/engine.js`，与 CLI 同一套规则；改规则请先改 `src/`，再重新打包该文件（文件头有说明）
